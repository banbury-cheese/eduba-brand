# Eduba Product Voice

Use this file for in-app copy, workflows, tool surfaces, buttons, forms, and system states.

## Tone

- calm
- exact
- useful
- never theatrical

The product should sound like a strong operator, not a founder thread.

## Core rules

- Be direct.
- Prefer verbs over slogans.
- Explain only what helps the user act.
- Avoid hype words like "unlock", "revolutionary", "game-changing", "magic", "seamless".
- Avoid marketing abstractions like "empower", "leverage", "reimagine", "future-proof".

## Buttons

Good:
- `Open Case`
- `View Project`
- `Ask For Access`
- `Start A Conversation`
- `See All`

Bad:
- `Unlock The Future`
- `Transform Your Workflow`
- `Explore Possibilities`

## Empty states

Good empty states describe:
- what this area is
- why nothing is here yet
- what the user should do next

Example:
> No case studies have been added yet. Add the first entry to start building the archive.

## Errors

Errors should be plain and specific.

Good:
> This file could not be uploaded. Try a smaller image or a different format.

Bad:
> Something went wrong.

## Success states

Keep them brief.

Good:
- `Saved`
- `Invite sent`
- `Review updated`

## Tooltips and help text

Tooltips:
- one sentence
- concrete
- no persuasion

Help text:
- explain the implication, not the obvious field name

Example:
> This label appears in the public archive tab.

## Section headings

Headings should be declarative and spare.

Good:
- `Build What Makes Sense`
- `Govern What Works`
- `Case Studies`

Bad:
- `Solutions For Modern Teams`
- `The Future Of Intelligent Transformation`

## Notifications and toasts

Keep them compact and neutral.

Good:
- `Coming soon`
- `Link copied`
- `Project opened in a new tab`

## Product voice vs marketing voice

If the user is inside the product:
- use this file

If the user is reading editorial, marketing, social, or founder-led content:
- use `voice/VOICE.md`
